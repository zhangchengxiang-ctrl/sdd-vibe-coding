# 委派策略（Claude Code 指挥 ⇄ Codex / 便宜子代理执行）

> 真源：2026-11-17 两轮评测（详见文末证据）。目标：**指挥侧只做高智能、低 token 的事**（架构 / Spec / 验收裁决），
> 实现与测试循环下沉到便宜通道；用户全程只和指挥侧对话。本文是 `dispatch-codex` 的路由与协议层，
> 边界闸门仍以 [`codex-boundary.md`](./codex-boundary.md) 为准，本文不放宽它。

## 0. 成本的真实结构（先理解这个，再谈路由）

指挥侧会话每多一轮就要重读整个上下文：上下文约 30 万 token 时**每轮约 $0.07**（官方标价折算）。
一个 Haiku 调度器跑完一个任务才约 $0.008，Haiku 直接实现一个中等任务约 $0.025–0.05，Sonnet 约 $0.21–0.64。
所以**主会话的轮数**才是成本主角，不是执行器的 token：

- 一次启动多个互不依赖的切片（一轮），后台跑完，**读一次**紧凑结论（一轮）。禁止逐切片守着。
- 不轮询。后台命令/子代理结束时系统会通知；自己写的后台驱动要保证**一定会退出**（墙钟超时），并且必须是被系统跟踪的后台任务，否则收不到通知。
- 不要在 20 万+ 上下文的长会话里做机械活；机械活交出去，指挥侧只保留裁决。

## 1. 路由矩阵

| 通道 | 何时用 | 配置 | 证据 |
|---|---|---|---|
| **L0 指挥侧自做** | Plan / Spec / Oracle 设计、架构取舍、UI 与产品判断、需要生产授权或用户决策、安全敏感设计、风险行为的审查 | — | 边界规则 |
| **L1 Codex（默认）** | 过 `codex-boundary` 的 Build 切片：机验 Oracle、文件级白名单 ≤8、单切片 | `gpt-6.1-sol` + `low`，墙钟 1200s，一次一个切片 | 3 个真实任务 3/3 通过，盲评均分最高，token 少于 terra/medium |
| **L2 便宜 Claude 子代理** | 小而机械的整理（单文件、新增 ≲100 行），或 Codex 额度耗尽时的退路 | 显式 `model: "haiku"` | Haiku 直接做 3/3 通过、约 $0.03/任务、H3 盲评并列最佳 |
| **L3 Claude Code + DeepSeek** | **不作默认**。仅在 L1/L2 都不可用、且任务简单时人工选择 | `claude -p --model kaon/deepseek-v4.1-flash-1017`，显式 `--allowedTools` 白名单，轮数上限 ≥150 | 2/3 通过；最难任务 80 轮未完成；比 Haiku 慢 3–5 倍且标价不低于 Haiku |
| **避免** | Sonnet 直接做机械活（成本约 Haiku 的 11 倍，盲评反而更低）；`luna` 做非机械任务（任何档位）；`terra/low` 做难任务 | — | 矩阵 |

选 L1 还是 L2 的判据：切片已经满足 `codex-boundary` 且预计要多轮"改-测"循环 → L1；一两处小改、写 Pack 的成本比改动本身还大 → L2 或自己做。

## 2. Codex 档位阶梯（只有这一条阶梯，不要自创）

1. 默认 `gpt-6.1-sol` / `low`。
2. 配额耗尽（`failure_class=quota`，退出码 75）→ 降到 `gpt-6.1-terra` / `medium`（该组合 3/3 通过，质量略低），**不要改代码，也不要当作能力失败**。
3. 验收红（Oracle 未绿 / 行为评审有 CRITICAL）→ **一次**补修：同档位，把失败证据原文附在 Pack 末尾再派（fix-11 实测一轮即修好）。
4. 仍红 → 升 `gpt-6-astra` / `medium` **一次**。
5. 仍红 → 指挥侧接手，并在 `run.md` 写 `executor: conductor` 与原因。不得无限重试。

升 effort 不是升级手段：两次独立测量里都没有因为升 effort 变好（见 `SKILL.md` 口诀）。`luna` 仅用于 `sdd-mech`（机械改），且未在本评测里验证，保持现状。

## 3. 验收协议（执行者的自述不是证据）

指挥侧**不读 diff 全文**，按下面四道门，全部由脚本或独立评审完成：

- **V1 Oracle 重放**：`ship.sh` 先红后绿；不绿不收。
- **V2 回归对比**：逐条测试结果对基线，**先去掉参数化 ID 里的随机串（UUID）**再比；`PASSED → 非 PASSED` 视为回归。数据库依赖的用例不能当绿灯 Oracle（本机无库时它们基线就报错）。
- **V3 行为评审（"行为不变"类任务必做）**：类型整理 / lint / 重构 / 删除这类任务，Oracle 与回归**抓不到行为改动**。必须由**另一个上下文、另一个模型**做盲评，逐项检查：SQL 与返回值是否变化（如 `== True` 改成 `.is_(True)`）、异常类型与 None 路径、API 输出（如空串变 None）、有没有用 `Any` / `cast` / `type: ignore` / `noqa` 把问题藏起来、有没有越出白名单。**出现 CRITICAL 不得合入**，按阶梯第 3 步补修。
- **V4 隔离审计**：Codex 沙箱是 `danger-full-access`，只能在隔离 worktree 里跑。抽查命令日志：是否读了 worktree 之外的路径、是否读 git 历史（防抄答案）。

## 4. Spec / Oracle 的写法（约定已写进 `codex-boundary.md`，这里只列清单）

- Oracle 命令里的测试路径写**仓库根相对路径**；经运行器切目录会让 `ship.sh` 的"评判者基线是否存在"检查误判。
- 负控（"保留项仍在"）必须与变更**合取**，保证基线为红。
- 冻结测试若 `monkeypatch` 某个模块符号，Spec 必须**点名该符号**，否则实施者只能猜。
- 后端 pytest 只在 Docker 里跑（项目规则），所以 Oracle 需要隔离运行器：一次性容器、`--network none`、只读或绑定挂载 worktree；容器镜像不得留存含环境变量的快照。
- 旧格式 Spec（自由格式切片表）转成可派发格式是指挥侧的一次性成本：规划新 Spec 时就写成"纵向切片 + 触及路径 + T-id 映射"。

## 5. 子代理与嵌套代理的安全约束

- 启动子代理**必须显式传 `model`**：本环境默认 `CLAUDE_CODE_SUBAGENT_MODEL` 是 Haiku，不写就悄悄用它。
- 嵌套启动 `claude -p` **不得**带 `--dangerously-skip-permissions`（会被自动模式拦截，也确实削弱监督）；用显式 `--allowedTools` 白名单（读写编辑、Oracle 脚本、只读 `git`）。
- Codex 只在隔离 worktree 里运行；临时 profile、临时镜像评测完即删；不把令牌、环境变量写进日志或镜像。
- 运行 `codex exec` 必须重定向 stdin（`< /dev/null` 或文件），否则会无限挂住。
- 生产相关动作仍须逐目标授权，委派不改变这条红线。

## 6. 失败处理速查

| 现象 | 含义 | 动作 |
|---|---|---|
| 退出 75 / `failure_class=quota` | 额度窗口烧穿，没连上模型 | 阶梯第 2 步，不改代码 |
| 退出 124 / 137 | 墙钟到点 | 先看仓库产物是否已达标，再决定补修 |
| 无 `turn.completed` / 无 `run_state=finished` | 进程被杀或崩溃 | 判失败，重派，不当成功 |
| 执行者报告 "blocked"、补丁为空 | 诚实的失败（实测出现过） | 当作有效信号，走阶梯第 3–4 步，不要重复同一配置 |
| 执行者撞到轮数/时间上限 | 未完成 | 查产物，必要时升通道，不是 Oracle 的问题 |
| 通知迟迟不来 | 后台任务不在系统跟踪内，或卡死 | 自己的驱动必须有墙钟超时，并用被跟踪的后台任务启动 |

## 7. 要记录的（为了下一次重新校准）

每个被委派的切片在 `run.md` 记：通道、模型、effort、耗时、token（输入/缓存/输出）、结果类别（通过 / 部分 / 阻塞 / 失败）、补修次数、V3 评审是否有 CRITICAL。
模型或网关变更、或累计 20 次派发后，**重新做一次评测**：≥3 个真实未做过的任务、实施前预注册判据与分级规则、盲评、同基线、多通道对照、成本用实测 token。方法与上一轮一致，不要用已交付任务回放（答案会漏进输入）。

## 8. 已知局限（别把它当成定论）

- 每个配置只跑了一次，没有方差估计；盲评 1 分以内的差距是噪声，可靠的只有"做成/没做成"和评审点出的行为改动。
- 任务都是静态类型整理，没覆盖需要设计决策的难度。
- **订阅额度的消耗读不到**：CLI 与模型目录都没有成本权重。`gpt-6.1-sol` 作默认是基于质量与 token 的推断，历史上曾因全部钉在 Sol 烧穿额度（75 次里 6 次），所以阶梯第 2 步是硬约束，且累计 20 次后要看 `quota` 失败占比。
- Claude 与 DeepSeek 的金额是按官方标价折算；你的网关实际计费未知。
- `gpt-5.6-*` 在模型目录里是"旧一代"，本评测没测它们，仍保留在白名单里。
