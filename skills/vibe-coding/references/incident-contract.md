# Incident Contract

> 本文件是生产 Diagnose、Incident、止血、部署授权和恢复验证的唯一真源。

## 1. 环境门

任何线上判断前，先从用户描述和宿主 `AGENTS.md` 确认：

- 环境与 URL；
- 当前版本 / commit；
- 日志、监控、SSH、数据库和运行时入口；
- 部署与回滚命令；
- 生产操作授权。

不确定环境时只做安全的只读调查或询问。禁止用本地日志、数据库或配置代表生产。

## 2. Diagnose

“排查、看看为什么、线上出错”默认只授权 Diagnose：

1. 固定时间范围、影响用户和关键标识；
2. 记录表象与已确认事实；
3. 建立 2–3 个可证伪假设；
4. 读取真实环境证据；
5. 排除假设并定位根因层；
6. 输出根因置信度、风险和下一 Work Order。

Diagnose 禁止未授权写代码、改配置、改数据或部署。

## 3. Incident 触发

满足任一才进入 Incident：

- 核心服务不可用；
- 活跃数据损坏或丢失风险；
- 活跃安全事件；
- 核心用户旅程严重故障且无合理绕过。

其余问题回到普通 Repair / Plan。

## 4. Incident 流程

```text
确认影响
→ 选择止血
→ 最小变更
→ 发布前最低验证
→ 部署授权
→ 生产健康检查
→ 核心路径验证
→ 记录残余风险
→ 长期 Repair / Verify
```

止血优先级：

1. 回滚；
2. 功能开关；
3. 隔离故障依赖；
4. 配置修正；
5. 最小 Hotfix；
6. 大规模重构禁止进入 Incident。

任何代码、配置或功能开关变更前，先建立最小 Incident Work Order，至少固定：

- 恢复目标与当前影响；
- In / Out 和写入边界；
- 生产动作授权；
- Workspace / Branch / PR；
- 发布前最低验证、生产 Oracle 和回滚点。

事故记录可以承载这张紧急 Work Order，无需为止血创建完整版本包。

## 5. 授权边界

Incident 可以以“恢复生产”为一个对话目标，但以下动作仍需宿主预授权或用户明确授权：

- 数据删除、恢复或不可逆修复；
- 数据库迁移；
- 权限和安全边界；
- 生产部署；
- 关闭关键保护机制。

“排查”不包含这些授权。

## 6. Hotfix Workspace

Local 有功能 WIP、需要稳定分支或需要独立紧急 PR 时，优先独立 Worktree。直接回滚、
配置止血或干净工作区中的唯一事故不强制 Worktree。所有选择仍服从
`workspace-contract.md`。

## 7. 生产验证

至少记录：

- 目标环境和版本；
- deploy / rollback 结果；
- health；
- 原始故障信号是否消失；
- 核心用户路径；
- 数据一致性；
- 监控观察窗口；
- 未覆盖项和回滚点。

`production-restored` 只表示服务恢复，不表示长期根因、回归或产品债已完成。

## 8. 安全与复盘

- 日志和证据必须脱敏；
- 不把生产密钥写入仓库、聊天或 evidence；
- 不为验证猜想修改生产状态；
- 重大事故在宿主定义的事故目录记录时间线、根因、止血、恢复和后续 Task；
- 暴露系统性问题时回填产品/技术 Gap；
- 完整回归可以在恢复后执行，但必须有明确 Work Order。
