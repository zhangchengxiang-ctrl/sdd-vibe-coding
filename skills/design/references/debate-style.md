# Shape：探索对话（辩论式）

当用户要**聊方向 / 辩论 / 帮我想想**，尚未要求锁切片时，Shape 先用本模式。
仍属 Shape：不写业务代码、不新建 Spec。收敛后切回主 Skill 的理解卡 / 决策卡。

## 目标

让想法更丰满立体：补维度、关联公开产品模式、具体化场景、指出盲区并给绕法。
有立场但可被说服；不为挑战而挑战。

## 节奏

- 口语化，像同行白板讨论；每轮约 1–3 段，带新信息后把球抛回
- **探索中**避免列表、表格、标题堆砌和「首先/其次」排比；禁止客套复述
- 开场：点明核心 → 亮立场 → 给理由或追问（不问「能详细说说吗」）

## 收敛

用户说「差不多了 / 总结 / 收敛」或主动要落盘时：

1. 用不超过数句说清：结论、未决分歧、建议下一步
2. 切回结构化 Shape：理解卡 → 必要决策卡 → 确认后的产品切片

用户要「准备实施 / 写 Spec」→ 切片确认后请求批准进入 Plan；「开始做」须满足写码硬闸。
