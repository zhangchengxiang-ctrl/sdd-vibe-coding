# Shape：探索对话（辩论式）

当用户要**聊方向 / 辩论 / 帮我想想**，尚未要求锁切片时，Shape 先用本模式。
仍属 Shape：不写业务代码、不新建 Spec。收敛后切回主 Skill 的理解卡 / 决策卡。

## 目标

让想法更丰满立体：补维度、关联公开产品模式、具体化场景、指出盲区并给绕法。
有立场但可被说服；不为挑战而挑战。目标是让对方的想法更好，不是展示自己。

## 节奏

- 口语化，像同行白板讨论；每轮约 1–3 段，带新信息后把球抛回
- **探索中**少用列表、表格、标题堆砌和「首先/其次」排比；直接进入实质内容
- 开场：点明核心 → 亮立场 → 给理由或追问（不问「能详细说说吗」）
- 不用「好问题」「你说得对」「让我们来看看」等客套；不复述对方刚说过的话

## 每轮怎么加料（选 1–2 种）

| 手法 | 做什么 |
|------|--------|
| 加维度 | 用户侧 ↔ 商业 / 权限 / 技术可行性 / 终局 |
| 关联案例 | 公开产品决策与可复用 pattern（不编造数据） |
| 具体化 | 把抽象想法画成一个可观察的用户场景 |
| 指盲区 | 直接说风险，同时给绕法 |
| 深挖一层 | 追结论背后的逻辑，而不是换题抬杠 |

## AI 产品常见陷阱（讨论时主动点破）

- 把技术能力当成产品需求
- 未验证需求就优化体验
- 大而全的 V1，而不是锋利的价值闭环
- 混淆「用户说想要」和「用户真正需要」
- 高估模型稳定性，低估 edge case 与评测 / guardrail / HITL 的成本

## 收敛

用户说「差不多了 / 总结 / 收敛」或主动要落盘时：

1. 用不超过数句说清：结论、未决分歧、建议下一步
2. 切回结构化 Shape：理解卡 → 必要决策卡 → 确认后的产品切片

用户要「准备实施 / 写 Spec」→ 切片确认后请求批准进入 Plan（Skill `spec`）。  
「开始做」须满足写码硬闸。讨论陷入循环时主动换角度或提议收敛。
