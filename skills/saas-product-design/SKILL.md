# SaaS Product Design

把业务任务变成可实施的页面方案：**信息架构决定看什么，交互决定怎么做，视觉决定先看到什么。** 三者一起设计，不以“高级、现代、简洁”代替决定。

这是设计能力入口，不是第二套设计系统或交付流程。先读宿主 AGENTS、品牌/设计系统及代表页面；沿用宿主技术栈、组件、权限规则。只加载本节直接列出的相关参考，不遍历参考中的链接，也不复活已归档页面手册。

## 1. 先确定页面服务的决定

用几句话明确角色、主任务、成功结果、频率、动作后果和权限范围。先用已有上下文回答；只有缺失项会改变方案时才追问，尚未确认的业务政策标为假设。

中后台通常是 Operate；长报告可为 Read，首次接入可强调引导。不要因“SaaS”就生成营销hero或四张等大的指标卡。

改存量先读变更边界。**视觉延续与业务影响分别判断**：保留导航壳或沿用视觉不代表非 material。主任务路径、交互单位、权限可见性或跨面入口改变时，明确其影响与批准需求，不得因标注 refinement 就按 polish 放行；也不要为交互调整强制重做整套视觉。

## 2. 选择骨架，写出内容优先级

选能支持主任务的结构，不按数据库实体平铺。以下是选择提示，不是穷举模板：

| 页面 | 主判断 | 方案中要说清 |
|---|---|---|
| 概览 / 分析 | 发生了什么，接下来处理什么 | 摘要层级、异常、下钻路径、时间/范围/来源 |
| 列表 / 审批队列 | 找到对象并处理 | 首要识别列、筛选、动作、批量范围、返回上下文 |
| 详情 / 报告 | 理解对象并作决定 | 关键结论/状态、正文证据、次要元数据、相关对象 |
| 表单 / 设置 | 安全地改变配置 | 字段分组、依赖、保存单位、校验与未保存退出 |
| 专业工作台 | 持续探索或处理复杂任务 | 编辑与结果的关系、辅助栏、任务进度、恢复入口 |
| 接入引导 | 达成首次可用 | 推荐路径、主动作、必要步骤、实际成功信号 |

给一个文本线框或区域顺序，并列出“常驻、按需展开、移出页面”的信息。说明为什么选表格/列表/图表，以及为何采用行内、抽屉、弹窗或独立详情；不要每种容器都用一次。

## 3. 把交互写成行为，而非组件名

针对主任务写“触发 → 范围/前置条件 → 等待反馈 → 成功结果 → 失败恢复 → 返回位置”。沿用产品判断与交互文案参考，不另写第二份规则清单。

例如，批量动作不只写“支持多选”：说明当前页还是跨页、筛选变化后选中项如何处理、部分成功后怎么继续。长任务不只写“显示loading”：说明离开页面后从哪里找回。涉及金额、用量、预测时，说明单位、时间窗、权限范围与缺失数据如何影响判断。

把后端依赖与设计建议分开。按钮防重不等于服务端幂等；显示禁用不等于有权限隔离；提示“已复制”不等于完成接入。

## 4. 让视觉规格能落到组件

先用大小、字重、对齐、间距建立灰度层级，再决定颜色。沿用宿主token；没有宿主时读尺度、语义色与动效参考，输出所用角色与值的对应关系，不把默认表当随意建议，也不要宣称尚未测量的颜色已合规。

至少说明：

- 页标题、正文、辅助信息、数字和代码各用什么排版角色。
- 主内容与导航/工具栏谁突出；哪些边框、背景、阴影可以省掉。
- 标准/紧凑密度如何对应真实内容；长姓名、长SQL、数值和操作怎样排布。
- 明暗主题、窄分屏、触屏/键盘条件下哪些结构变化，哪些信息不能丢。
- 视觉特色放在哪里，以及为什么不影响连续操作。

输出前核对规格内部一致性：字号/控件/间距是否来自所声明的token源；例外有无理由与待确认项。不要说“沿用规范”，随后又给出一套不匹配的值。

## 5. 默认交付格式

按任务大小裁剪，不强制填满所有章节：

1. **页面定位与取舍**：推荐方向、保留什么、明确不做什么。
2. **信息架构**：文本线框、信息优先级、关键字段/导航。
3. **关键交互**：主路径、权限/批量/并发/长任务中实际相关的部分。
4. **视觉规格**：宿主token映射、层级、密度、响应式与长内容。
5. **状态与验收**：列出相关状态、可观察结果、待实现依赖和待人确认项。

仅要求方向时给短方案；用户明确要可实施设计时才展开。不要把设计讨论自动升级为编码、安装或部署许可。

## 6. 交付前自检

从真实任务反看方案：主动作找得到吗，关键判断信息同屏吗，错误后能继续吗，窄屏/键盘会不会丢掉主入口？用代表内容检查，不为了清单增加无关UI。

保留一条最强反方意见并裁决：建议是否打断已有心智、丢失专业密度、引入后端尚不支持的承诺？区分源码推断、运行观察与设计假设；不能看图就不作像素评分，未运行就不宣称验收通过。

**设计方案完成不等于页面交付完成。** 进入实施后仍走宿主批准流程与真实验证；本技能不替代 SDD 的授权、Spec、testing 或 deploy。
